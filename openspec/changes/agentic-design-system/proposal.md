## Why

VortSpec hands its agents a flat inventory and a slice of prose, then pays them to rediscover the
design system by grepping. There is no relationship graph (`grep usedBy` returns nothing), no way to
answer "is this component actually used", and the one genuinely rich metadata schema the project owns
(`.sdd-de/docs/component-metadata-model.md`) is generated by `/storybook`, rendered into a docs page,
and **read by no runtime code** — while the thing that actually reaches the model is a four-field
free-text record. The published benchmark for the architecture this change adopts (see
`docs/agentic-design-system-plan.md` §1.6) reports accuracy 65% → 100%, run-to-run variance 26.5% →
0.04%, false negatives 60% → 0%, at a **flat token cost (+3.5%)** — it reallocates spend from
exploration into analysis rather than adding spend.

## What Changes

- **One metadata schema, VortSpec-owned.** Widen `componentMetadataSchema` from four free-text fields
  to the nine sections (identity, usage, variants, aiHints, composition, behavior, props,
  accessibility, designTokens), keeping `.vortspec/metadata/<name>.json` as the store. Anti-patterns
  become a structured `{scenario, reason, alternative}` triplet; variants gain a `purpose` map and
  `aiHints` gains `selectionCriteria` — the fields that let an agent *choose* rather than guess.
- **BREAKING (toolkit-internal): `<Name>.metadata.ts` stops being an authored artifact.** `/storybook`
  and `.storybook/ComponentDocs` become *readers* of `.vortspec/metadata/*.json`. Storybook is
  demoted to a human-validation surface, exactly like the token views. Legacy four-field records are
  migrated on read, so existing projects keep working.
- **A relationship graph and consumption measurement — new capability, absent today.** Recursive
  `uses`/`usedBy` import chains keyed on full project-relative paths (never filename stems), instance
  counts parsed from template bodies rather than imports, per-component efficiency, and
  shadow-implementation detection. Persisted as TOON under `.vortspec/ai/`.
- **A query-protocol layer.** Generated rules under `.vortspec/ai/rules/` (metadata schema, atomic
  hierarchy, deep tracing, load-once discipline), and the already-vendored-but-unwired skills
  (`ai-ds-composer`, `ai-component-metadata`, `codebase-index`) reachable from real runs.
- **The light page path gets selection criteria.** `buildLightPagePrompt` currently gives the model
  `designer.md` — strong token discipline, zero guidance on *which* component or variant to pick and
  zero anti-patterns. Per-component hints are added to the manifest, framework-free.
- **Governance moves from existence to intent.** Today `buildDesignAudit` has two rules
  (`hardcoded-color`, `token-drift`) — both "does this token exist". Adds hierarchy, elevation,
  semantic-color and typography-composite rules that catch a syntactically valid token used in the
  wrong position, plus adoption and token-violation reports.
- **AI-readiness level as a product surface.** A computed 1–5 maturity level with the specific next
  action that raises it.
- `compose-run.ts`'s `DESIGN.md` `.slice(0, 4000)` is replaced by the structured digest — truncating
  prose at a byte boundary is the worst available use of those tokens.

## Capabilities

### New Capabilities
- `component-metadata`: the unified, VortSpec-owned structured record per component — schema, store,
  generation, migration, and the readers (runtime prompts, Storybook docs, Design System view).
- `design-system-index`: the codebase index — inventory, recursive relationship graph, instance and
  adoption counts, shadow-implementation detection, TOON artifacts, freshness, and how the digest
  exposes it to a run.
- `agent-query-protocols`: the rules layer that teaches an agent to navigate the index instead of
  exploring — including skill wiring and the hints handed to the light-page path.
- `design-governance`: intent-level design rules, the violations they produce, and the adoption /
  token-violation reports generated from the index.
- `ai-readiness-level`: the computed maturity level and the next action that raises it.

### Modified Capabilities
- `design-system-workspace`: "Rich per-component Storybook docs" changes ownership — Storybook docs
  are rendered *from* `.vortspec/metadata/*.json` rather than from a `<Name>.metadata.ts` that
  `/storybook` authors. Storybook becomes a reader; metadata exists with or without it.

## Impact

**Code**
- `packages/core/src/shared/inspector.ts` — `componentMetadataSchema` widened (+ migration of the
  legacy shape); `AuditFinding.kind` extended.
- `packages/core/src/main/inspector/` — `component-metadata.ts` (new schema + prompt), `index-digest.ts`
  (bounded relationship section), `design-audit.ts` (intent rules); new `relationship-index.ts`,
  `adoption-report.ts`, `readiness-level.ts`.
- `packages/core/src/shared/lite-manifest.ts` — `LiteComponent` gains a framework-free `hints` block;
  must still pass `findFrameworkPointers`.
- `packages/core/src/shared/light-page.ts` — `buildLightPagePrompt` carries selection criteria and
  anti-patterns for in-scope components.
- `packages/core/src/shared/compose-run.ts:295` — drop the `DESIGN.md` `.slice(0, 4000)`.
- `packages/ui/src/views/` — Design System / Inspector Issues surfaces for reports and the readiness
  level.

**Toolkit**
- `.sdd-de/docs/component-metadata-model.md` — rewritten for the new ownership.
- `.sdd-de/ai-specs/skills/storybook/SKILL.md` — reads metadata instead of authoring it.
- `.sdd-de/ai-specs/skills/{ai-component-metadata, ai-ds-composer, codebase-index}` — wired in
  (vendored already, currently unreachable).

**Artifacts on disk (new)**
- `.vortspec/ai/{index.toon, component-usage.toon, design-tokens.toon}`
- `.vortspec/ai/rules/*.md`, `.vortspec/ai/governance/*`, `.vortspec/ai/reports/*.md`

**Dependencies**
- None added. The indexer is implemented in TypeScript on the existing B2 scan cache — the vendored
  `codebase-index` Python script is a reference implementation, not a runtime dependency, so the
  Electron app gains no Python requirement.

**Cost**
- Interactive runs stay roughly flat (bounded digest growth traded against eliminated grepping).
  Report generation is new, off the interactive path, and routed to the cheapest capable model
  (Haiku), consistent with existing verify/Apply routing.

**Interactions**
- `light-design-system` (unarchived) owns `designer.md` via its `lite-design-manifest` delta; the
  hints block extends that shape and must land compatibly.
- `figma-mapping-index-plan`'s B1–B6 work is the foundation this builds on (scan cache, durable maps,
  digest, metadata store) — this change completes B6 and adds the graph layer B-plan never specified.
